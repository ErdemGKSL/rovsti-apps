## Owner rules for this round
- Rosty names everywhere (`dev.rosty.stops`, `rosty_*` crates, "Rosty" in strings).
- WhatsApp parts (arriving-soon chat rows, anything over `:wa`) and every algorithmically complex part (tile rasterising,
  projection, camera zoom/pan/fling maths, geofence and distance, nearest stop, arrival estimation, tile LRU and eviction,
  pin hit-testing and snapping geometry) are built by Fable subagents; each writes its approach under "Approach" below.
  Domain rules stay in platform-free Rust (`rosty_geo`, `rosty_core`, `rosty_app_core`) with unit tests; per-frame UI
  number policies (camera maths) are pure Kotlin with JVM tests cross-checked against the Rust `view.*` fixtures (ARCH 0, 8.4).
- Release builds only (`--profile checks` / `--release`, Gradle `*Release*` tasks). No signing keystore, no `google-services.json`.
